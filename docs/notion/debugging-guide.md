# 디버깅의 아홉 가지 원칙

[문서 목록](./README.md) · [Notion 원문](https://pengsida.notion.site/1b69debf803a4c268fc8a09a9a748bbf)

원저자는 코드 문제로 실험이 멈추는 일을 줄이기 위해 이 자료를 정리했습니다. 질문에 답할 때 해결 방법뿐 아니라 어떤 디버깅 원칙을 적용했는지도 설명하겠다고 합니다.

내용은 David J. Agans의 *Debugging*과 [독서 정리 글](https://brainku.github.io/2016/12/11/debugging-the-9-rules/)을 바탕으로 합니다. 첨부된 책 PDF·전자책의 전문 번역 대신 원칙과 연구에 적용할 질문을 요약합니다.

| 원칙 | 연구 코드에서 확인할 것 |
| --- | --- |
| 시스템 이해 | 모듈의 역할과 정상적인 입력·출력을 설명할 수 있는가? |
| 오류 재현 | 같은 환경·데이터·모델에서 문제가 다시 생기는가? 간헐적 오류의 조건을 기록했는가? |
| 관찰에 근거한 판단 | 추측을 로그·중간값·시각화·중단점으로 확인했는가? |
| 범위를 나누어 추적 | 작은 데이터와 설정으로 원인이 있는 구간을 좁혔는가? |
| 한 번에 하나씩 변경 | 정상 사례와 실패 사례의 차이, 마지막 정상 버전 이후의 변경을 비교했는가? |
| 기록 유지 | 수행 순서, 바꾼 조건, 결과를 남겼는가? |
| 가정 점검 | 데이터와 디버깅 도구도 틀릴 가능성을 확인했는가? |
| 다른 관점 구하기 | 문제를 설명하고 동료·전문가·공개 자료·AI의 도움을 검토했는가? |
| 근본 원인 해결 | 증상만 줄인 것은 아닌가? 재현 조건으로 수정 결과를 확인했는가? |

원문은 여러 버그가 함께 있으면 범위를 좁히기 어렵다고 설명합니다. 발견한 원인을 하나씩 수정하고 다시 확인하는 과정이 필요합니다. AI의 답변 역시 관찰과 실험으로 검증할 가설입니다.
