# 심사 의견에 답변하는 법

[연구 가이드 목록](./README.md) · [한국어판 처음으로](../../README.md)

원문: [공개 Notion](https://pengsida.notion.site/af99ce47103e4917b6a5bd1fd4b3c022) · [Sida Peng의 Learning Research](https://github.com/pengsida/learning_research)

원문 확인일: 2026년 11월 4일.

## 답변의 문체와 구성

1. 질문받은 내용을 바로 답합니다. 관계없는 설명은 심사자의 주의를 분산시킵니다.
2. 어떤 질문에 답하는지 문단 앞부분에 표시합니다.
3. 가능하면 심사자가 질문한 순서대로 답합니다.
4. 심사자별 구역에 모든 질문을 적고 하나씩 답합니다. 공통 답변을 따로 묶었더라도 각 심사자 구역에서 해당 답변을 가리킵니다.

원문에는 이러한 문체를 보여 주는 PDF 예시가 첨부되어 있습니다.

## 1. 심사 의견 정리하기

먼저 **심사자가 왜 이 점수를 주었는지** 설명할 수 있어야 합니다. 원저자는 전체 구조를 보기 쉬운 draw.io 정리를 권하고, 원문에 편집용 템플릿과 그림을 제공합니다.

공개된 그림의 흐름은 다음과 같습니다.

1. 목표는 심사 의견에 충실히 답하고, 그 의견을 바탕으로 논문을 개선하는 것입니다.
2. 그러려면 심사자가 무엇을 뜻했는지 이해해야 합니다.
3. 심사 의견은 문맥 속에서 읽어야 합니다.
4. **심사자 한 명씩 의견 전체를 읽고 맥락을 이해한 뒤**, 각 질문에 답합니다.
5. 그다음 여러 답변의 중복 부분을 공통 질문으로 묶어 분량을 줄입니다.

처음부터 심사자의 문장을 잘게 쪼개 비슷한 문장끼리 묶으면 각 심사자의 의도가 사라질 수 있다는 점을 그림에서 경고합니다.

이전 스프레드시트 방식도 참고할 수 있습니다: [작성 예시](https://docs.google.com/spreadsheets/d/1TS2l5SrbExHxA1i_xrm2Sbd5dz_uS4CqAjoAskiZNX0/edit?usp=sharing), [빈 양식](https://docs.google.com/spreadsheets/d/17sH8sMqroFrmLKfogcC-9AyJpWKi8Ugru1NoKtFAIDo/edit?usp=sharing).

## 2. 평가 근거와 약점에 답하기

점수의 근거와 약점 항목에서 제기한 문제를 직접 다룹니다. 심사자가 읽자마자 어떤 질문의 답인지 알 수 있어야 합니다. 요청받은 근거를 제공하고, 답변 과정에서 설명되지 않은 새 논점을 불필요하게 만들지 않도록 합니다.

참고 글: [Devi Parikh의 답변서 작성법](https://deviparikh.medium.com/how-we-write-rebuttals-dc84742fece1), [SIGGRAPH 답변서 작성 가이드](https://research.siggraph.org/blog/guides/writing-a-rebuttal-for-siggraph/).

## 3. 초안을 핵심 쟁점 중심으로 검토하기

초안을 쓴 뒤 각 심사자의 핵심 우려에 표시하고, 정확하게 답했는지와 설득력이 있는지를 반복해서 확인합니다. 동료에게도 검토를 부탁하세요.

원저자는 긴 심사평에도 평가를 좌우하는 핵심 쟁점은 몇 개일 때가 많다고 설명합니다. 모든 질문에 성실히 답하되, 초안 이후의 검토에서는 특히 그 핵심 쟁점에 시간을 들이라는 뜻입니다.

> 첨부 범위: 공개된 설명과 도표는 한국어로 옮겼습니다. 별도 PDF 예시와 편집용 draw.io 파일의 전문 대조는 첨부 자료 상태에 따로 기록합니다.
