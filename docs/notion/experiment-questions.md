# 실험 결과를 분석할 때 던질 질문

[연구 가이드 목록](./README.md) · [한국어판 처음으로](../../README.md)

원문: [공개 Notion](https://pengsida.notion.site/4be609919b914b7587a5477bddc83001) · [Sida Peng의 Learning Research](https://github.com/pengsida/learning_research)

원문 확인일: 2026년 11월 4일. 별도 표시가 없는 조언은 원저자의 견해입니다.

원문의 제목은 ‘실험 결과 분석의 고전적인 열 가지 질문’이지만, 현재 본문에는 주제별로 아홉 항목이 있습니다. 항목 수를 맞추기 위한 질문을 새로 만들지 않았습니다.

## 코드 점검

1. 각 모듈의 중간 출력은 예상과 일치하는가? [알고리즘과 코드 디버깅](https://pengsida.notion.site/1b69debf803a4c268fc8a09a9a748bbf)을 참고합니다.
2. NaN이나 세그멘테이션 오류처럼 흔한 버그의 원인을 점검했는가? [NaN 원인과 점검법](./nan-debugging.md)을 참고합니다.

## 실패 사례

3. 실패 사례에는 일정한 규칙이나 반복되는 패턴이 있는가? 그 패턴이 기술적 원인을 드러낼 수 있습니다. 실패를 잘 시각화하는 능력이 중요합니다. 원문에는 관련 디버깅 일화 이미지 두 장이 첨부되어 있습니다.

원문이 소개한 3D 시각화 도구: [Wis3D](https://github.com/zju3dv/Wis3D), [Iridescence](https://github.com/koide3/iridescence), [Viser](https://github.com/nerfstudio-project/viser).

## 데이터 점검

4. 테스트 데이터에서 성능이 나쁘다면 학습 데이터에서는 어떤가? 학습 데이터에 과적합할 수는 있는가?
5. 더 단순한 데이터에서는 어떤 결과가 나오는가?
6. 이전에 잘되던 데이터와 지금 데이터는 무엇이 다른가? 그 차이가 실패를 설명하는가?

## 알고리즘 점검

7. 같은 데이터에서 잘되던 기존 알고리즘에 비해 현재 방법은 왜 나쁜가? 구성 요소를 하나씩 제거하거나 바꿔 보면 어느 모듈이 문제인지 드러나는가? 구현 오류는 아닌가?
8. 현재 알고리즘을 단순화한 버전은 작동하는가? 성능은 어떤가?
9. 의심되는 모듈의 출력을 시각화했는가? 예상과 맞는가, 이상한 현상이 보이는가?
