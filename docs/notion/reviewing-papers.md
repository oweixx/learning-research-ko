# 논문을 검토하는 기준

<!-- editorial:summary -->
**세 줄로 먼저 읽기 · 한국어판 요약**

- 독자가 새롭게 배우는 것이 무엇인지 기여를 중심으로 평가합니다.
- 중요한 비교 방법·평가 지표·구성 요소 분석이 빠지지 않았는지 살핍니다.
- 얻는 이점과 함께 새로 생기는 제약도 검토합니다.
<!-- /editorial:summary -->

원문 확인일: 2026년 11월 4일. 아래의 조언과 견해는 별도 표시가 없으면 원저자의 설명입니다.

원저자는 심사에서 거절 사유가 될 만한 요소를 하나씩 점검하라고 권합니다. 아래는 원저자가 정리한 기준이며, 모든 학회가 동일하게 사용하는 공식 심사표는 아닙니다.

## 좋은 평가를 받기 위한 세 가지 조건

1. **충분한 기여가 있습니다.** 새로운 과제, 전체 방법, 구성 모듈, 설계 선택, 실험적 발견, 통찰<!-- term:insight -->([문제를 푸는 방향을 이끄는 핵심 생각](../guides/glossary.md#핵심-통찰-insight))<!-- /term --> 가운데 하나 이상을 의미 있게 제공합니다.
2. **기존 방법보다 좋은 실험 결과를 보입니다.**
3. **구성 요소 분석과 비교 실험이 충분합니다.**

## 흔한 거절 사유

| 항목 | 점검할 내용 |
| --- | --- |
| 기여 부족 | **독자가 새롭게 배우는 것이 있는가?**<!-- highlight --> 해결하려는 실패 사례가 이미 익숙하거나, 제안 기술이 충분히 연구되어 성능 향상이 쉽게 예상되는 것은 아닌가? |
| 불명확한 글 | 재현에 필요한 기술적 세부 사항이 빠져 있지 않은가? 각 모듈을 도입한 이유가 설명되어 있는가? |
| 부족한 성능 | 개선 폭이 지나치게 작지는 않은가? 이전 방법보다 좋아졌더라도 과제를 해결하기에 충분한 수준인가? |
| 불충분한 검증 | **구성 요소 분석, 중요한 비교 방법, 중요한 평가 지표가 빠져 있지 않은가?**<!-- highlight --> 데이터가 너무 쉬워 실제 효과를 입증하지 못하는 것은 아닌가? |
| 방법 설계의 문제 | 실험 조건이 현실적인가? 기술적 결함이 있지는 않은가? 장면마다 하이퍼파라미터<!-- term:hyperparameter -->([학습률 등 학습 과정이나 모델 구성을 정하는 설정값](../guides/glossary.md#하이퍼파라미터-hyperparameter))<!-- /term -->를 다시 맞춰야 할 정도로 불안정하지 않은가? **얻는 이점보다 새롭게 생기는 제약이 더 크지는 않은가?**<!-- highlight --> |

원문의 첨부 그림도 직접 대조했습니다. 그림에 담긴 다섯 범주와 세부 항목은 위 표에 모두 반영했습니다.
