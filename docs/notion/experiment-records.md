# 실험 기록 작성하기

<!-- editorial:summary -->
**세 줄로 먼저 읽기 · 한국어판 요약**

- 나중에 다시 이해할 수 있도록 목적과 변경한 실험 설정을 남깁니다.
- 성공·실패 결과를 모두 기록하고 수치와 시각화로 관찰을 뒷받침합니다.
- 예상과 다른 이유를 분석하고 이어서 할 실험을 적습니다.

원문 확인·번역일: 2026년 11월 4일. 본 페이지의 본문을 한국어로 옮겼습니다. 연결된 별도 문서의 번역 상태는 외부 자료 진행 현황에서 구분합니다.

실험 기록은 보통 다음 순서로 작성합니다. 지나치게 자세히 쓸 필요는 없습니다. 주로 자신이 다시 확인하기 위한 기록이므로, **나중에 읽었을 때 이해할 수 있을 정도**<!-- highlight -->면 됩니다.

1. **실험 목적:** 왜 이 실험을 하는지, 무엇을 알아내려는지 적습니다.
2. **실험 설정:** 어떤 데이터로 실험했는지, 알고리즘에서 무엇을 바꿨는지 적습니다.
3. **실험 결과:** **잘된 결과와 잘되지 않은 결과를 모두 남깁니다.**<!-- highlight --> **시각화 결과와 정량적 수치를 함께 기록합니다.**<!-- highlight -->
4. **결과 분석:** 결과가 예상과 일치하는지 확인합니다. 예상과 다르다면 [실험이 기대대로 되지 않는 원인](./experiment-failures.md)을 분석합니다.
5. **다음 단계:** 프로젝트를 이끄는 사람은 자신입니다. 지시를 기다리기보다 다음에 무엇을 할지 계속 생각하고, **이어서 수행할 실험을 적습니다.**<!-- highlight -->

## 한국어판 비교 예시: 실험 기록: 성공 여부에서 다시 판단할 수 있는 기록으로

이해를 돕기 위해 만든 가상 예시입니다. 원저자의 발언이나 실제 실험 결과가 아닙니다.

### 아쉬운 예

> 오늘 설정을 바꾸니 결과가 좋아졌다. 이 설정을 쓰면 될 듯하다.

### 개선한 예

> 목적: 경계 오류가 입력 선택 방식과 관련 있는지 확인한다. 설정: 같은 데이터와 학습 설정에서 입력 선택 방식만 바꾼다. 관찰: 비교한 한 장면에서는 경계가 안정적으로 보였다. 분석: 다른 장면에서도 유지되는지는 미확인이다. 다음: 실행 버전·명령·결과 경로를 남기고 추가 장면에서 수치와 시각화를 함께 비교한다.

**달라진 점:** 실험 목적과 변경 요소를 명시하고 관찰의 범위를 한정했습니다. 실제 기록에는 데이터 식별자, 코드 버전, 설정과 결과 파일 위치를 구체적으로 채웁니다.
