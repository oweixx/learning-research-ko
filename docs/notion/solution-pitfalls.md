# 기술적 해결책을 구상할 때 겪기 쉬운 문제

<!-- editorial:summary -->
**세 줄로 먼저 읽기 · 한국어판 요약**

- 평소 논문을 직접 찾고 폭넓게 읽으며 사용할 수 있는 기술을 늘립니다.
- 떠오른 해결책을 혼자 확신하기 전에 지도교수와 여러 동료에게 설명합니다.
- 다른 사람의 질문과 의견을 통해 접근의 허점과 놓친 가능성을 점검합니다.

## 1. 기존 연구에서 배우지 않고 처음부터 구상하기

관련 분야의 논문에서 얻을 수 있는 지식을 활용하지 않은 채, 자신의 생각만으로 전체 처리 과정을 설계하는 문제입니다.

## 2. 지도교수가 찾아 주는 논문에 의존하기

스스로 관련 논문을 충분히 찾지 않으면 생각의 폭이 좁아집니다. 그러면 해결책을 구상할 때 익숙한 생각에서 벗어나지 못해 더 나은 기술을 제안하기 어렵습니다.

**평소 직접 논문을 찾고 폭넓게 읽습니다.**<!-- highlight --> 원저자는 **현재 프로젝트와 직접 관련된 분야에서는 지도교수보다 더 많은 논문을 읽는 것**을 하나의 기준으로 제시합니다. 이 기준에 못 미치면 프로젝트가 실패할 가능성도 높다고 봅니다.

## 3. 구상한 해결책을 다른 사람과 논의하지 않기

지도교수와 연구실 동료에게 아이디어를 설명하지 않으면, 자신의 생각에 갇혀 더 나은 방법을 찾지 못할 수 있습니다.

**해결 아이디어가 생기면 적어도 한 번은 지도교수와 여러 동료에게 이야기하고 의견을 들어 보세요.**<!-- highlight --> 원저자는 이 과정을 거치지 않은 프로젝트가 뛰어난 결과를 내기는 어렵다고 봅니다.

## 4. 기술적 기여가 없는 방법 만들기

프로젝트의 처리 과정에 새로운 기술적 기여가 없으면 논문으로 쓰기 어렵습니다. 논문으로 작성하더라도 독창성<!-- term:novelty -->([기존 연구와 비교해 새롭게 제시한 점](../guides/glossary.md#독창성-novelty))<!-- /term -->이 부족하다는 심사 의견을 받을 수 있습니다.

원문은 [논문의 기술적 기여도를 높이는 법](https://pengsida.notion.site/434a6b3e34d0403ca178fb0db2338232)을 참고 자료로 안내합니다. 이 별도 페이지는 현재 조회되지 않아 본문을 확인하지 못했습니다.
